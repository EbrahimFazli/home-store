## ۱. مقدمه

### ۱.۱ هدف سند
این سند داستان‌های کاربر (User Stories) پروژهٔ هوم‌استور را تعریف می‌کند.
هر User Story از دید کاربر نوشته شده و معیار پذیرش دارد.

### ۱.۲ قالب User Story
هر User Story به این شکل نوشته می‌شود:

> **به‌عنوان** [نقش]، **می‌خواهم** [کاری] **تا** [ارزش].

### ۱.۳ معیارهای INVEST
- **I**ndependent — مستقل
- **N**egotiable — قابل مذاکره
- **V**aluable — ارزشمند
- **E**stimable — قابل تخمین
- **S**mall — کوچک
- **T**estable — قابل تست

### ۱.۴ اولویت‌بندی MoSCoW
- **Must:** بدون این، پروژه بی‌معنی است
- **Should:** مهم، اما اگر وقت نشد بعداً
- **Could:** خوب است داشته باشیم
- **Won't:** در این نسخه نداریم

## ۶. معیار پذیرش نمونه

### US-01 — نمایش محصولات

**به‌عنوان:** مشتری
**می‌خواهم:** محصولات را ببینم
**تا:** انتخاب کنم

**معیار پذیرش:**
- [ ] صفحهٔ محصولات با حداقل ۲۰ آیتم نمایش داده شود
- [ ] هر آیتم شامل تصویر، نام، قیمت باشد
- [ ] بارگذاری صفحه < ۲ ثانیه باشد
- [ ] صفحه در موبایل و دسکتاپ واکنش‌گرا باشد

### US-06 — افزودن به سبد خرید

**به‌عنوان:** مشتری
**می‌خواهم:** محصول را به سبد خرید اضافه کنم
**تا:** بعداً خرید کنم

**معیار پذیرش:**
- [ ] دکمهٔ «افزودن به سبد» در صفحهٔ محصول باشد
- [ ] سبد خرید بلافاصله به‌روز شود
- [ ] تعداد کل اقلام در هدر نمایش داده شود
- [ ] پیام موفقیت نمایش داده شود

### US-11 — ثبت سفارش

**به‌عنوان:** مشتری
**می‌خواهم:** سفارش ثبت کنم
**تا:** محصول را دریافت کنم

**معیار پذیرش:**
- [ ] فرم شامل نام، آدرس، تلفن باشد
- [ ] اعتبارسنجی همه فیلدها انجام شود
- [ ] بعد از ثبت، شماره پیگیری نمایش داده شود
- [ ] ایمیل تأیید ارسال شود (شبیه‌سازی)

### US-15 — افزودن محصول توسط ادمین

**به‌عنوان:** ادمین
**می‌خواهم:** محصول جدید اضافه کنم
**تا:** کاتالوگ به‌روز بماند

**معیار پذیرش:**
- [ ] فرم شامل نام، دسته، برند، قیمت، موجودی باشد
- [ ] امکان آپلود تصویر وجود داشته باشد
- [ ] زمان افزودن < ۲ دقیقه باشد
- [ ] بعد از ذخیره، در لیست محصولات نمایش داده شود
